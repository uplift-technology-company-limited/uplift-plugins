## 1. Executive Summary

**สถานะ: งานจากการตรวจ UX เสร็จในโค้ดแล้ว 4 จาก 12 ใบ อีก 8 ใบยังมีงานค้าง ซึ่งมีเพียง 3 ใบที่ต้องเขียนโค้ดเพิ่ม**

**ผลต่อผู้ใช้ตอนนี้**

จุดที่เคยเป็นทางตันถูกแก้ในโค้ดแล้ว

- พนักงานไม่เจอข้อความ "ติดต่อ HR" ผิด ๆ ในหน้าสลิปแล้ว (HRX-101)
- เอกสารที่หมดอายุเซ็นไม่ได้แล้ว (HRX-104)

ทั้งหมดนี้ยืนยันจากการอ่านโค้ดบน dev เมื่อ 13 ต.ค. ยังไม่ได้เดินหน้าจอจริง

**งานที่เหลือ 8 ใบ แบ่งตามคนที่ต้องลงมือ**

| ประเภท | จำนวน | ใครลงมือ |
|---|---|---|
| ต้องเขียนโค้ดเพิ่ม | 3 ใบ | ทีม dev |
| รอการตัดสินใจก่อนเริ่มได้ | 2 ใบ | เจ้าของผลิตภัณฑ์ |
| แก้ข้อมูลหรือตั้งค่าในระบบ ไม่ต้องเขียนโค้ด | 2 ใบ | ผู้ดูแลระบบ |
| ต้องตรวจซ้ำบน dev ก่อนสรุปได้ | 1 ใบ | QA |

**เรื่องใหม่ที่ต้องรู้**

ระหว่างตรวจพบว่าหน้าสรุปการลาไม่จำกัดข้อมูลตามบริษัทของผู้ดู เรื่องนี้ไม่อยู่ใน 12 ใบเดิม และควรเปิดใบแยก

**ขั้นถัดไป**

1. ตอบคำถาม 2 ข้อที่รอการตัดสินใจ (หัวข้อ 5)
2. เตรียมข้อมูลทดสอบบน dev แล้วเดินตรวจ 5 ใบ (หัวข้อ 6)
3. เริ่มงานโค้ด 3 ใบ เรียงตามลำดับในหัวข้อ 3

## 8. How We Close

ลำดับการทำ

1. เจ้าของผลิตภัณฑ์ตอบคำถามในหัวข้อ 5 คำตอบลงเป็นคอมเมนต์ในใบนั้น
2. เตรียมข้อมูลทดสอบบน dev ตามที่ระบุในหัวข้อ 6 แล้วเดินตรวจ
3. ผู้ดูแลระบบทำงานในหัวข้อ 4 ทำคู่ขนานกับข้อ 2 ได้
4. ทีม dev ทำงานโค้ดในหัวข้อ 3 ตามลำดับในตาราง
5. เปิดใบใหม่สำหรับเรื่องในหัวข้อ 7 ก่อนลงมือแก้

เกณฑ์ย้ายสถานะ

- ย้ายเป็น On Dev ได้เมื่อโค้ดอยู่บน dev แล้ว และมีคนเดินหน้าจอจริงบน dev จนเห็นว่าผ่าน
- ใช้ Rework เมื่อตรวจแล้วพบว่างานยังมีบั๊กเท่านั้น ใบที่ติดเพราะไม่มีข้อมูลทดสอบไม่ใช่ Rework

หลักฐานที่ต้องแนบในใบทุกครั้งที่ย้ายสถานะ

- ตรวจอะไร เห็นอะไร พร้อมตัวเลขหรือข้อความที่ขึ้นบนหน้าจอ
- ภาพหน้าจอจาก dev
- เวอร์ชันที่ตรวจ
- สิ่งที่ยังไม่ได้ตรวจ
